# 问答流程

状态采用文末两道确认流程；需求通过后只生成人物预览。

盘点已有信息，只问缺项；先确定三图角色，再确定人物、文案、元素、交互与交付。缺图用聊天文字索取，不用纯文本问答控件请求上传。

人物照片中以“左侧抱孩子的成年人”等可观察位置指代，不猜亲属关系；单人也确认是否寿星。无帽子、无修脸、无署名、无场景提取均可，只需明确记录。

不要固定发长问卷。每轮 1–3 个相关问题，优先提供清楚选项；推荐不等于用户选择。“由你设计”只覆盖用户明确指明的范围，最终仍须确认整份方案。

确认单：
- 三张图分别承担的角色。
- 保留人物、寿星、帽子、姿态服装与允许的外貌修改。
- 封面、内页、署名的完整文案和语言。
- 纸艺结构与后/中/前分层。
- 风格要点和从人物图提取的元素及来源。
- 功能、交付目录、离线或发布及访问范围。
- 禁止改变的部分、授权助手决定的部分。

结尾询问：“请确认是否按以上方案开始制作，或指出需要修改的地方。”
等待用户明确回复。仅确认其中一项不算全案确认；含糊回答则澄清。不要用沉默或计时替代同意。
已有作品的完整明确修改请求本身是修改授权，只补问新歧义。

## 新版两道确认（优先于旧流程）
状态：collecting → clarifying → awaiting_brief_confirmation → generating_character → awaiting_character_confirmation → building → review → delivered。
需求确认后先只生成人物预览。展示具体图片并询问“这版人物是否确认，可以开始制作网页吗？” 用户提出修改则回到人物生成，不创建网页。
用户只说“服装颜色对了”等仅确认局部的回复，不足以批准整个人物。明确“这版可以，继续”可接受。已批准人物不能在网页阶段重新生成或替换。
人物相关问答明确：约3头身程度、保留五官/发型/服装颜色、照片裁切、完整手持道具、白描边阴影和悬浮要求。
